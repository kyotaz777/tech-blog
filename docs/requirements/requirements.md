# AWS Tech Blog 要件定義

## 1. 背景・目的

現在はインフラエンジニアとしてオンプレミス環境を中心に経験している。

AWSについては過去に小規模プロジェクトで設計・構築を経験しているものの、現在の業務ではAWSを利用する機会がない。

そのため、資格取得だけではなく、自分自身でAWS上のサービスを設計・構築・運用し、実践的な経験を増やすことを目的として本プロジェクトを実施する。
また作成したアプリ上でも技術のアウトプットができるように技術ブログアプリとした

個人用技術ブログの構築・運用を通して、主に以下を実践する。

* AWSの設計・構築
* TerraformによるInfrastructure as Code
* CI/CD
* 運用・監視
* 技術アウトプット
* 技術ナレッジの蓄積
* GitHubによる成果物・変更履歴の管理

最終的には、AWSエンジニア、特にSRE寄りの業務につながる経験を作り、転職・案件面談時に説明できるポートフォリオとする。

## 2. システム概要

AWS上に個人用の技術ブログを構築する。

ブログはインターネット上に公開し、一般ユーザーは公開済みの記事を閲覧できる。

記事の管理は管理者のみが行う。

初期段階では機能を必要最小限に絞り、ブログとして利用するために必要な機能を優先して実装する。

SEOや収益化は第一目的としない。

## 3. ユーザー

### 3.1 一般ユーザー

認証を必要とせず、公開済みの記事を閲覧できる。

### 3.2 管理者

認証後、記事を管理できる。

初期段階では管理者のみを認証対象とし、一般ユーザー向けのユーザー登録・ログイン機能は実装しない。

## 4. 機能要件

### 4.1 記事閲覧

一般ユーザーは公開済みの記事を閲覧できること。

### 4.2 管理者認証

管理者は認証情報を使用してログインできること。

認証された管理者のみが記事管理機能を利用できること。

### 4.3 記事作成

管理者は新しい記事を作成できること。

記事は最低限、以下の情報を持つ。

* タイトル
* 本文
* 公開状態
* 作成日時
* 更新日時

### 4.4 記事編集

管理者は既存の記事を編集できること。

### 4.5 記事削除

管理者は既存の記事を削除できること。

### 4.6 記事公開

記事には公開・非公開の状態を持たせること。

一般ユーザーが閲覧できるのは公開状態の記事のみとする。

## 5. 非機能要件

### 5.1 Infrastructure as Code

AWSリソースは可能な範囲でTerraformによって管理する。

AWS環境の構成をコードとしてGitHub上に残し、変更履歴を確認できる状態とする。

### 5.2 CI/CD

GitHub上のコード変更をもとに、アプリケーションをAWS環境へデプロイできる仕組みを構築する。

CI/CDにはGitHub Actionsを利用する。

具体的なデプロイ方式についてはAWSアーキテクチャ設計時に決定する。

### 5.3 セキュリティ

以下を基本方針とする。

* WebサイトへのアクセスにはHTTPSを使用する
* AWS認証情報をGitHubリポジトリへ直接保存しない
* IAM権限は必要最小限とする
* 管理者向け機能は認証済みユーザーのみ利用可能とする
* データベースをインターネットへ直接公開しない構成を検討する

### 5.4 運用・監視

サービス公開後の運用を想定し、AWS上で監視の仕組みを構築する。

最低限、以下を監視対象として検討する。

* アプリケーションの正常性
* アプリケーションエラー
* AWSリソースの状態
* ログ
* AWS利用料金

具体的な監視項目・閾値については運用設計時に決定する。

### 5.5 可用性

個人利用の技術ブログであるため、商用サービス相当の高可用性は必須としない。

学習目的とコストのバランスを考慮してAWS構成を決定する。

### 5.6 コスト

個人学習用の環境であるため、継続して運用可能なAWS利用料金に抑える。

具体的な月額目標についてはAWSアーキテクチャ決定時に設定する。

## 6. 技術スタック

### 6.1 Frontend

* TypeScript
* Next.js

Frontendは画面表示およびユーザー操作を担当する。

### 6.2 Backend

* Python
* FastAPI

Backendは記事管理、認証、データベースアクセスなどのAPIを提供する。

FrontendとBackendを分離し、それぞれ独立したアプリケーションとして構築する。

### 6.3 Database

* PostgreSQL

主に以下のデータを保存する。

* 管理者情報
* 記事情報

### 6.4 Infrastructure

* AWS
* Terraform

具体的に利用するAWSサービスについてはアーキテクチャ設計時に決定する。

### 6.5 CI/CD

* GitHub Actions

## 7. 初期スコープ

初期リリースでは以下を実装する。

* 公開済み記事の閲覧
* 管理者認証
* 記事作成
* 記事編集
* 記事削除
* 記事の公開・非公開管理
* AWS上へのデプロイ
* TerraformによるAWSリソース管理
* GitHub ActionsによるCI/CD
* 基本的な監視

## 8. スコープ外

初期リリースでは以下を対象外とする。

* 一般ユーザー向けアカウント登録
* 一般ユーザー向けログイン
* コメント機能
* いいね機能
* SNS機能
* 複数管理者を前提とした高度な権限管理
* 高度なSEO対策
* 広告・アフィリエイトなどによる収益化
* 大規模アクセスを前提とした設計
* 商用サービスレベルのSLA

必要になった場合は、初期リリース後の追加要件として検討する。
